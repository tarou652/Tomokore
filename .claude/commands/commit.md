# コミット

変更内容を確認してコミットを作成する。

## 手順

1. `git status` と `git diff` を並列で実行して変更を把握する
2. `git log --oneline -5` で最近のコミットメッセージスタイルを確認する
3. ステージすべきファイルを選定する（`.env` や機密ファイルは除外）
4. 変更の種別と内容に合ったコミットメッセージを日本語で作成する（下記「コミットメッセージ規約」に従う）
5. `git add` で該当ファイルをステージし、コミットを作成する

## コミットメッセージ規約

### フォーマット

```
<type>: <理由>ため、<変更内容>
```

例: `feat: ピクセルグリッドを見やすくするため、ズーム機能を追加`

### type 一覧（Angular.js 規約）

| type       | 説明                                                             |
| ---------- | ---------------------------------------------------------------- |
| `feat`     | 新しい機能の追加                                                 |
| `fix`      | バグの修正                                                       |
| `docs`     | ドキュメントのみの変更                                           |
| `style`    | 空白・フォーマット・セミコロンなど、コードの意味に影響しない変更 |
| `refactor` | バグ修正でも機能追加でもないコード改善                           |
| `perf`     | パフォーマンス向上のための変更                                   |
| `test`     | テストの追加・修正                                               |
| `chore`    | ビルド・補助ツール・ライブラリ関連の変更                         |

### ルール

- **理由を含める**: `chore: hogeを追加` ではなく `chore: ネットワーク通信するため、hogeを追加`
- Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com> を末尾に付ける

## 実行前の確認

コミットメッセージのドラフトをユーザーに提示し、確認を得てからコミットする。
